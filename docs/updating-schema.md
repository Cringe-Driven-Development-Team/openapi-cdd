# Как обновлять сгенерированный код

Сгенерированных файла два, оба коммитятся и руками не правятся:

| Файл | Откуда берётся | Команда |
| --- | --- | --- |
| `spec/openapi.json` | выгрузка ветки Apidog | `bun run apidog` |
| `src/api/schema.ts` | генератор из `spec/openapi.json` | `bun run generate` |

Источник истины — ветка `main` в [Apidog](https://app.apidog.com/project/1382426). Контракт меняется там,
а не в этих файлах.

## Один раз: токен

1. В Apidog: Account Settings → API Access Token → создать личный токен.
2. `cp .env.example .env` и вписать токен в `APIDOG_TOKEN`.

`.env` в `.gitignore`, в git он не попадает. Bun читает `.env` сам.

## Обычное обновление

```sh
bun run sync        # apidog + generate одной командой
bun run typecheck   # код, который пользуется клиентом, всё ещё сходится с контрактом?
git diff            # что изменилось в контракте
```

Дальше:

- `typecheck` зелёный — закоммитить `spec/openapi.json` и `src/api/schema.ts` вместе, одним коммитом.
- `typecheck` красный — контракт изменился несовместимо: поправить вызовы, на которые указывает `tsc`
  (в этой репе это `src/demo.ts` и `src/type-errors.ts`), и только потом коммитить.
- `git diff` пуст — контракт не менялся, делать нечего.

Проверить вживую: `bun run demo` — пять запросов в облачный мок Apidog.

## Sprint-ветка Apidog

Пока Merge Request в Apidog на ревью, можно генерировать из sprint-ветки:

```sh
APIDOG_BRANCH_ID=1389936 bun run sync
```

ID ветки — серое число в Manage Sprint Branches. В `main` репы должен попадать только код,
сгенерированный из `main` Apidog: после слияния Merge Request в Apidog запустить `bun run sync` ещё раз
без `APIDOG_BRANCH_ID`.

## Только перегенерировать типы

Если спека не менялась, а менялся сам генератор (`src/generator.ts`):

```sh
bun run generate
```

Токен и сеть для этого не нужны.

## Если команда упала

| Сообщение | Что делать |
| --- | --- |
| `не задан APIDOG_TOKEN` | вписать токен в `.env` |
| `Apidog отклонил токен (401/403)` | токен неверный или отозван — создать новый |
| `APIDOG_BRANCH_ID должен быть положительным целым числом` | в переменной не ID ветки |
| `generate: #/paths/…: …` | в контракте конструкция, которую генератор не поддерживает; JSON pointer показывает место в `spec/openapi.json`. Либо упростить контракт в Apidog, либо добавить поддержку в `src/generator.ts` |

Генератор намеренно падает, а не подставляет `unknown`: молча потерянный тип хуже ошибки.

## В проекте-потребителе

Там, где пакет установлен из npm, спека выгружается своим скриптом, а типы генерирует CLI пакета:

```sh
bunx openapi-cdd ./openapi.json -o ./src/api/schema.ts
```

Правила те же: `schema.ts` коммитится, руками не правится, после генерации — `tsc`.
